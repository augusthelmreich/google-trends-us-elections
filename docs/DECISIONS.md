# Decision log

One line per decision: what was chosen, and why. Newest at the bottom.

| Date | Decision | Reason |
|---|---|---|
| 2026-10-02 | Repository rebuilt from scratch rather than importing earlier project code | Earlier versions had overlapping scope and inconsistent structure; rebuilding each step verifies it |
| 2026-10-02 | Raw Google Trends API responses are kept out of git | Google's Research API guide describes raw data as non-transferable |
| 2026-10-07 | Outcome is two-party Democratic share; target is its change since the previous election | Comparable across years with different third-party strength; cost: third-party surges appear as major-party swings (Utah 2016, +12 pp) |
| 2026-10-07 | Errors reported as a mean component (the year's mean state-level miss) and a geographic component (spread) alongside MAE | In 2024 all errors share a sign, so MAE equals the mean miss and cannot register geographic improvement; the split makes the test interpretable |
| 2026-10-08 | Topic IDs are validated by geography before use; raw API responses cached once and never re-requested | Geography is the only check that catches a wrong entity; the 2020 unemployment map tracks the unemployment rate (NV, KY, NJ, MI on top), so topic meaning must be checked, not assumed |
| 2026-10-12 | Search window is Aug–Sep of each election year | Latest whole-month window that ends before early voting; identical across years; two months limits zeros |
| 2026-10-12 | Topic eligible only if no state is zero in any training year | A zero is below-threshold, not zero interest; immigration excluded (24→6 zeros, 2008–2024) |
| 2026-10-12 | Candidate maps validated by home-state rank AND top-3 states | For general-election nominees top states are battlegrounds (DC, NH, VA, CO), i.e. campaign attention, which the D−R contrast largely cancels |
| 2026-10-12 | Primary metric is MAE on raw swing; geo_mae (MAE after removing the year's mean error) is reported alongside | Raw MAE is dominated by the year's mean swing, which centred state features cannot affect; geo_mae isolates what they can |
| 2026-10-12 | Uncertainty stated by permutation (shuffle features across states within year), not by bootstrap over states | States within an election are not independent draws; the permutation null asks the question that matters: do the features carry state-specific information |
| 2026-10-19 | Search data collected and scored with the `globaltrends` package (Puhr & Müllner 2021; GitHub 0.2.1, Research API backend); decided before the package run had finished and before any package-path result was seen | It is the instrument its authors built for this API and its control-basket score keeps years on one scale; the direct one-term-per-request pull stays as a robustness path in `src/robustness/` |
| 2026-10-19 | Package scores go through the same centring step as the API maps (divide by the cross-state mean, subtract 1) | Training pools years, so features must be comparable across years; the control basket's own drift over 2008–2024 would otherwise enter the feature; with the same step the two paths differ only in the denominator, which is what the comparison should isolate |
| 2026-10-19 | A map that is zero in all 51 states is treated as all states below threshold (feature at the floor, topic ineligible) | Scaled jointly with a control term, immigration rounds to zero everywhere in the package in every year; the topic was already ineligible on the API path |
| 2026-10-19 | Results reported for both paths; an effect that appears on one path only is called fragile, not a finding | With the three-topic model the package path showed a small geographic gain (shuffle benchmark p = 0.002 pooled) that the API path did not; with the five-topic model (2026-10-29) neither path shows one; the index test fails on both |
| 2026-10-29 | Forecasting models use every issue topic in the dictionary that passes the coverage rule (five topics), the same set as the ownership index | One dictionary and one rule for both tests; the first evaluation had used three topics fixed before the extended topics were added, and those results remain in the commit history |
| 2026-10-29 | Topic dictionary marks topics only as included or excluded; all permutation tests use 10,000 draws | The earlier core/extended split described the order topics were added, not a difference in use; different draw counts for the same kind of test had no reason |
| 2026-11-02 | Candidate topics are validated by one written rule before any result is seen: consensus-owned issue with two sources for the sign, a Google entity that is the concept, no zero state in any training year, a stable map across elections (`src/dictionary/check_topics.py`); the check uses maps from all five elections, so the test years inform the measurement design though never the model fitting | Health care (`/m/01mw2x`) is a health-industry map and does not replace health insurance; the broad `Immigration` entity passes and replaces the narrow one; Social Security, national debt and foreign policy fail coverage |
| 2026-11-02 | Unemployment stays in the forecasting models but leaves the ownership index (`own_sign` 0) | Noble 2025 C.2 codes jobs Democratic and the economy Republican; Fagan folds both into a contested macroeconomics category; a search for unemployment belongs to both, so the sign is undetermined by the sources |
| 2026-11-02 | Index robustness block gains a side-balanced variant (mean of Democratic topics minus mean of Republican topics) | The dictionary has two Democratic and three Republican topics; the variant shows whether the count matters (it does not: −0.08 vs −0.07) |
